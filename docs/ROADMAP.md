# ロードマップ

## 目的

汎用のアンケートアプリを、管理者が自分でデプロイして使える形で配布する。\
管理者は設問定義ファイルと環境変数を用意し、起動するだけで使い始められる。

スキルシート作成アプリは、このアプリの利用例の1つとして扱う。

## 基本構成

- アプリを、機能（エンジン）と設問定義（コンテンツ）に分ける。
- 1つのインスタンスで扱うアンケートは1テーマ。
- 回答形式（チェックと5段階評価）、画面の流れ、結果表示、CSV、共有は、\
  現在の機能をそのまま使う。
- 配布するのは、バックエンドを Go で実装した版。\
  Spring Boot 版は、アプリの機能を固めるための実装として使い、配布しない。

## 設問定義

- 定義ファイルを唯一の正とする。\
  管理画面、管理者の認証、DB 上のマスタは持たない。\
  DB に保存するのは回答だけにする。
- 管理者は、Docker や基本的なインフラを扱える技術者を想定する。
- 設定は JSON の2ファイルに分ける。
  - 設問の定義（`survey.json`）：カテゴリ・設問・選択肢。バックエンドも扱う。
  - 表示設定（`display.json`）：フロントだけが解釈する。
    - アプリ名、TOP の説明文、結果ページの見出し、CSV の見出しとファイル名
    - 尺度の名前と、5段階それぞれの説明
    - カテゴリのアイコン
- 尺度は5段階で固定する。細かくする必要が出たら、その時点で対応する。
- サンプル定義を2種類同梱する（スキルシートと、別のテーマを1つ）。
- 版は、設問の定義ファイルの内容から計算したハッシュ値で識別する。\
  版が変わったら、保存済みの回答と、ブラウザに残った入力途中の状態を無効にし、\
  利用者に知らせる。
- 検証は、エディタ（JSON Schema）・コミット時のテスト・起動時の3段で行い、\
  同じ規則を使う。

## 配信と任意機能

- 既定は同一デプロイ（バックエンドが画面も配信する）。\
  環境変数を設定した場合のみ、フロントを別にデプロイできる。
- PDF 生成は、AWS の環境変数を設定した場合のみ有効にする。
- バックエンドなしで動くモードはやめる。

## 段階

1. 新しいリポジトリを作る（完了）
2. 定義の形とコンテンツの範囲を決め、JSON Schema を作る
3. フロントを、定義から画面を組み立てる形に整理する
4. 定義をバックエンドに移す（読み込み・検証・版・API）。\
   e2e テストを、バックエンドありの形に変える
5. 同一デプロイと、任意機能（別デプロイ・PDF）の切り替えを作る
6. 公開中のスキルシートを、このリポジトリからの配信に切り替える
7. バックエンドを Go で置き換える
8. 配布用に整備する（`docker compose`、設定の説明、定義ファイルの検証コマンド）

段階1〜6は Spring Boot 版で進める。

段階6では、既存の DB にこのリポジトリのマイグレーションが適用される。\
バックエンドを先に、フロントを後に切り替える。

段階7で既存の DB を引き継ぐ場合は、Flyway の適用履歴の扱いを決める必要がある。
