# 決定事項

日常の作業で守るルールは `.claude/rules/` にまとめている。\
この文書には、方針に関わる決定と、ルールに書ききれない理由を残す。

## 2026-10-31 汎用アンケートアプリへの移行

- 汎用化すると、アプリの中身が旧リポジトリ名（CreateSkillSheet）と食い違う。\
  そのため、ブランチではなく新しいリポジトリ（survey-sheet）に切り出した。
- 旧リポジトリのコミット履歴を引き継いだ。\
  方針転換の経緯を、履歴から追えるようにするため。
- 設問の差し替えは、管理者が定義ファイルを編集して再起動する形にする。\
  管理者が自分でデプロイする前提なら、画面からの編集機能と認証は不要なため。
- 設問を差し替えたら、以前の回答は使えなくする。\
  古い回答を古い定義で表示し続ける仕組みより、単純に保てるため。
- 定義ファイルの検証規則は1か所で実装し、テストと起動時で共用する。\
  規則が2か所に分かれると、片方だけ直して食い違う原因になるため。
- 配信は同一デプロイを既定にする。\
  導入が簡単で、フロントとバックエンドの反映のずれも起きないため。
- Node と Java のバージョンは `.nvmrc` と `.java-version` で指定する。\
  開発環境では Node を nvm、Java を OS のパッケージで入れており、\
  新しいツールを入れずに済むため。CI も同じファイルを参照する。
- `deploy.yml` は、手動実行のみにしている。\
  このリポジトリには、本番のデプロイ先をまだ設定していないため。
- `DESIGN_NOTES.md` は削除する。\
  旧リポジトリはポートフォリオとして設計を説明する目的だったが、\
  このリポジトリは配布が目的のため。
- `README.md` は、利用者が自分の環境に構築するための手順書にする。

## CI

- ブランチ保護の必須チェックは、集約ジョブ `ci-result` に一本化している。\
  `test.yml` の `paths-ignore` と必須チェックが衝突し、\
  `.md` だけの PR がマージできなくなる問題を、CI 側で解消するため。

## PDF 生成

- 生成のきっかけは PDF ボタンの押下。\
  名前確定時の保存による事前生成は、待ち時間を短くするための最適化。
- PDF が無いときに生成を依頼する経路は `regenerate`。生成失敗時の作り直しにも使う。
- 生成失敗の区別は、バックエンドのトラブルシューティングのためのもの。\
  利用者には通知しない。恒久的な失敗は、デプロイ時に確認する。
- S3 のライフサイクルルールの日数は、シートの保存日数（5日）とそろえる。\
  状態管理の項目を増やさないため。

## データ

- `shareToken` は拡張用に設計したが、現在は使っていない。\
  回答テーブルを作り直す段階4で、扱いを決める。
- `AnswerDto.value` に `@NotNull` を付けて、不正なデータが入らないようにしたい。\
  段階4で DTO を作り直す際に反映する。

## 命名

- `isCheckedByDefault` と `failureCount` は改名しない。
- 名前入力のフェーズ名に `revisable` は使わない（馴染みが無いため）。

## README 用の動画

- 作業ブランチにはコミットせず、メディア専用のブランチに置いて、\
  `raw.githubusercontent.com` から参照する。\
  更新のたびに履歴へ蓄積し、リポジトリが肥大化するのを防ぐため。
- 形式はアニメーション WebP。ライトとダークの両方を撮影し、\
  `<picture>` で切り替える。容量の目安は 5MB 以下、表示幅は 720px。

## 見送ったこと

- `tsconfig.json` の分割は行わない。必要になったら別の作業として扱う。
- CSV の書き出しに、PapaParse などのライブラリは導入しない。\
  依存を増やすほどの差が無いため。
