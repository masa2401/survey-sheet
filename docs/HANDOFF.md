## 次の作業

段階2で、まだ決まっていないことを決め、JSON Schema とサンプルを作る。

1. 回答者の名前：入力を残すか。入力欄のラベル、「様」、CSV のファイル名を表示設定で変えられるようにするか
2. `id` を手で書く運用を続けるか（版が変わると回答は無効になるため、振り直さない制約は弱まる）
3. JSON Schema で表せない検証の規則（`id` の重複、各階層の最低件数、文字数の上限）と、\
   表示設定（`display.json`）をどこで検証するか（バックエンドは中身を解釈しない）
4. 文言の既定値：汎用的な既定値をアプリに持ち、表示設定に書いた項目だけを上書きするか
5. カテゴリの件数による TOP の挙動\
   （案：選択式が0件なら選択欄を出さない。共通が0件なら1つ以上選ばないと開始できない。両方0件は定義のエラー）
6. 回答ページでのカテゴリの並び順（案：共通を先、選択式を後に、それぞれ定義の順）
7. 2つ目のサンプル定義のテーマ（尺度の意味やカテゴリの数がスキルシートと違うもの）
8. 画面の言語：固定の文言は日本語のままにし、多言語対応は対象外とするか
9. リポジトリ内の置き場所（設問の定義・表示設定・JSON Schema）
