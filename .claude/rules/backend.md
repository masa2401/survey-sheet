# バックエンド

- 層は controller・service・repository・entity・dto に分ける
  - dto は request と response を分け、入力の検証は request 側に持たせる
- 新しく作る処理は service の層に置き、その中で Spring に依存しない処理と、つなぐ処理を分ける
  - 検証・変換・CSV の組み立てなど、入力から結果を作るだけの処理は、Spring の注釈を付けない普通のクラスにする
  - `@Service` のクラスは、その処理を呼び、設定や DB とつなぐだけにする
- 例外とエラー処理は、細かく分けることより、トラブル時に問題箇所を特定しやすいことを優先する
  - 専用の例外クラスは、必要になってから作る
- DB のスキーマ変更は Flyway のマイグレーションで行う。適用済みのファイルは編集しない
- 外部への副作用（PDF の描画役への依頼など）は、トランザクションのコミット後に行う
  - トランザクションの外のメソッドから、コミットの後に呼ぶ
  - コミット前に実行されないことを、結合テストで確認する
- 子テーブルの削除は、外部キーの `on delete cascade` に任せる
- 検索や削除に使う外部キー列には、インデックスを明示的に追加する（PostgreSQL は自動で作らない）
- 期限切れデータの定期削除は、利用の少ない午前3時に実行する
