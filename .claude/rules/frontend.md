# フロントエンド

## 優先順位

- パフォーマンスより UX を優先する。\
  パフォーマンスだけを根拠にした提案はしない。
- 最適化は、UX に直結するかどうかで判断する。\
  ビルド時間の短縮は、明らかな無駄を省く程度でよい。

## コンポーネント

- `src/components/ui/**` は shadcn-vue の生成物なので編集しない。\
  `outline` variant の `dark:bg-input/30` も既定のまま使う。
- 独自の見た目の切り替えは、shadcn の `data-variant` と衝突しないよう、\
  `data-feedback` などの別の属性と、Tailwind のデータ属性バリアントで行う。
- 選択式の UI は `RadioGroup` を使い、`role="radio"` を保つ。\
  e2e のロケーターが依存している。
- 操作できない理由を示す要素は、`disabled` ではなく `aria-disabled` を使う。\
  操作自体は呼び出し側で止める。
- 入力欄の幅は、同じ文字列を持つ非表示の `<span>` を、\
  グリッドで `<input>` に重ねて決める。

## 配色

- 判断の根拠は WCAG と、このプロジェクトで決めた規約にする。\
  MD3 は出発点として使っただけで、準拠する義務はない。
- 純白と純黒は使わない。
- 情報の優先度で配色を決める。ラベルやタイトルの視認性を優先し、\
  操作要素が画面で最も明るい面にならないようにする。
- 面を暗くする案は、その面に載る文字の優先度を確認してから出す。
- 配色の変更は、ライト・ダーク両方のコントラスト比を確認してから行う。
- `--rating` は、ライトモードでは装飾として扱い、WCAG 非準拠を許容する。\
  星の情報は、隣の数値表示と重複しているため。\
  ダークモードは、意図してトーンを反転している。
- 明るい背景に `amber-500` は使わず、`text-rating` を使う。
- Web フォント（Noto Sans JP）は置き換えない。

## 挙動

- 進捗表示は、データの正確さより UX を優先する。\
  100% のまま張り付く表示は避ける。\
  処理が早く終わり、50% 前後で表示が切り替わるのは許容する。
- ルーティングはハッシュ方式。\
  クローラーの除外は、`index.html` の `noindex` でサイト全体に掛ける。
- 名前は確定後に固定し、再訪時も変更できないようにする。\
  名前を変えるたびに PDF 生成が走り、コストが増えるため。
- CSV は自前で実装する。\
  CSV インジェクション対策の `FORMULA_PREFIX` は `@/utils/constants` で管理し、\
  CSV 出力のエスケープと、名前入力の検証で共用する。
- 不正な名前は確定させず、`inputting` フェーズに留める。
